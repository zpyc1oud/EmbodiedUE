# Phase boundaries

A phase boundary is the point where one kind of work is complete and the next kind begins. Make context-management decisions at that boundary, using judgment about what the next work needs.

## Options

- **Continue** when the next work benefits from the current reasoning or the context is still useful.
- **Clear** when the current context is disposable and a clean start is more useful.
- **Handoff** when the work must travel to another harness, directory, repository, colleague, or side task.
- **Subagent** when a tightly scoped task can run independently without steering.
- **Compact** when the context remains relevant but a fresh summary will make the next phase easier to manage.

Preserve a relevant primary source when the next phase depends on decisions or rationale that a summary could flatten. Do not change context merely because a phase ended, and do not keep context that is no longer relevant.

These are judgment calls, not a mandatory order. Prefer the option that preserves the information the next phase needs with the least unnecessary context switching.
